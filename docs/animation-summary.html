01 — Overview

What Is the Animation System?

FandomVerse uses a scroll-driven, bidirectional animation system built entirely with vanilla CSS transitions and plain JavaScript — no external animation libraries required.

The core idea is simple: every animated element starts hidden or off-screen (via a CSS class), and a JavaScript scroll listener watches the viewport. When an element enters the visible area it becomes active and transitions into place. When it leaves, it transitions back out in the same direction it came from.

⚡

Zero Dependencies

Pure CSS transitions + vanilla JS. No GSAP, Anime.js, or AOS required.

🔁

Truly Bidirectional

Elements animate IN when scrolled into view and OUT in the same direction when scrolled away.

⌨️

Typewriter Effect

Text paragraphs type in character-by-character and delete themselves when the section leaves focus.

⏱️

Configurable Duration

Typing speed is set per-container via data-typing-duration, defaulting to 2 000 ms.

02 — CSS

Animation Classes

Each animation is defined as a pair of CSS rules in CSS/style.css. The base class sets the hidden starting state; adding .animate-active transitions the element into its visible final state.

Class Name Direction Effect (IN → active) Effect when removed (OUT)
.anim-slide-left ← Left Slides in from the left Slides back out to the left
.anim-slide-right → Right Slides in from the right Slides back out to the right
.anim-slide-up-zoom ↑ Bottom Rises up + scales in from below Sinks back down + scales out
.anim-zoom-in ● Center Scales from 92% → 100% Scales back to 92%
.anim-unblur ✦ Blur Fades in from heavy blur Blurs back out and fades
🔑 Key Principle

The transition property is declared on the base class (not on .animate-active). This means the transition applies in both directions — adding the class plays it forward, removing it plays it backward. No extra JavaScript is needed for the reverse motion of non-text elements.

CSS Definition Example — Slide Left

/* ── Initial (hidden) state ───────────────────── */
.anim-slide-left {
  opacity: 0;
  transform: translateX(-60px);
  transition: opacity 0.8s cubic-bezier(0.16, 1, 0.3, 1),
              transform 0.8s cubic-bezier(0.16, 1, 0.3, 1);
  will-change: opacity, transform;
}

/* ── Visible (active) state ───────────────────── */
.anim-slide-left.animate-active {
  opacity: 1;
  transform: translateX(0);
}
03 — JavaScript Engine

How the Scroll Engine Works

Located in js/script.js inside the initApp() function. The engine uses a scroll event listener with getBoundingClientRect() for reliable, precise viewport detection — replacing the earlier IntersectionObserver approach which fired too late for smooth reverse animations.

The "In Focus" Rule

function checkScrollAnimations() {
  const vh = window.innerHeight;

  animEls.forEach(el => {
    const r = el.getBoundingClientRect();

    // "In focus" = top < 85% of viewport AND bottom > 15%
    const inFocus = r.top < vh * 0.85 && r.bottom > vh * 0.15;

    if (inFocus && !el.classList.contains('animate-active')) {
      el.classList.add('animate-active');    // → CSS plays FORWARD
    }
    else if (!inFocus && el.classList.contains('animate-active')) {
      el.classList.remove('animate-active'); // → CSS plays BACKWARD
    }
  });
}

window.addEventListener('scroll', checkScrollAnimations, { passive: true });
requestAnimationFrame(checkScrollAnimations); // run once on load

Why scroll event instead of IntersectionObserver?

🚫

IntersectionObserver (Old)

Fires once when an element crosses a threshold. For large elements (like sliders), it stays "intersecting" even when mostly scrolled past — so the reverse callback fires too late or not at all.

✅

Scroll + getBoundingClientRect (New)

Runs on every scroll tick. Uses exact pixel positions to decide focus state — consistent and immediate in both scroll directions.

Full Lifecycle Flow

Page Loads
→
Elements hidden by CSS base class
→
User scrolls down
→
Element enters focus zone
→
+animate-active → CSS plays forward
User scrolls back up
→
Element leaves focus zone
→
−animate-active → CSS plays backward
→
Element back to hidden state
04 — Typewriter Effect

Typewriter Animation

The typewriter effect applies to any <p class="typewriter-text"> element that is a child of an .anim-slide-left or .anim-slide-right container.

Initialisation (on page load)

  • All .typewriter-text paragraphs have their text saved to data-original-text.
  • Their innerText is cleared and visibility: hidden is applied.
  • This ensures no text flashes before the animation runs.

Forward Animation (scrolling INTO view)

  • Total duration is read from data-typing-duration attribute on the container (default: 2 000 ms; About page uses 2 500 ms).
  • Total character count across all paragraphs is summed.
  • ms per character = max(8, floor(totalDuration / totalChars))
  • Paragraphs are typed sequentially with a 60 ms gap between them.
  • A blinking cursor (_) appears via CSS ::after while typing is active.

Reverse Animation (scrolling OUT of view)

  • Any running forward intervals are immediately cancelled via the activeTypewriters Map.
  • Paragraphs are processed in reverse order (last → first) to mirror the forward sequence.
  • Characters are deleted one-by-one at ~700 ms total deletion speed.
  • Each paragraph is hidden after its text is fully deleted.
  • When the section scrolls into view again, the typewriter restarts from scratch.
/* Blinking cursor CSS */
.typing-active::after {
  content: '_';
  display: inline-block;
  color: var(--primary-color);
  animation: blink-cursor 0.75s step-end infinite;
}
@keyframes blink-cursor {
  from, to { opacity: 0 }
  50%       { opacity: 1 }
}

07 — Extending

How to Add Animations to New Elements

The system is designed to be self-contained. Adding an animation to any new element requires only HTML changes — no JavaScript needed.

Step 1 — Add the animation class to the element in HTML

<!-- Zoom in from bottom -->
<div class="my-section anim-slide-up-zoom"> ... </div>

<!-- Slide in from left -->
<div class="my-box anim-slide-left"> ... </div>

<!-- Slide in from right -->
<div class="my-box anim-slide-right"> ... </div>

<!-- Un-blur fade-in (good for headings) -->
<h2 class="anim-unblur">Heading Text</h2>

The scroll engine automatically picks up all elements matching those class selectors.

Step 2 — Add a stagger delay (optional)

<!-- Title animates first, content follows 150 ms later -->
<h2 class="anim-slide-up-zoom">Section Title</h2>
<div class="anim-slide-up-zoom" style="transition-delay: 0.15s">
  ...content...
</div>

Step 3 — Add a typewriter effect (text paragraphs)

<!-- Container must be anim-slide-left or anim-slide-right -->
<div class="anim-slide-left" data-typing-duration="2000">
  <h2 class="anim-unblur">Section Heading</h2>
  <p class="typewriter-text">First paragraph text...</p>
  <p class="typewriter-text">Second paragraph text...</p>
</div>
⚠️ Important Notes

• data-typing-duration is in milliseconds. Omitting it defaults to 2 000 ms.
• The h2 with .anim-unblur is observed independently — it doesn't need to be inside the slide container to animate, but placing it inside means it resets automatically when the container leaves focus.
• transition-delay only affects the CSS transition direction. The scroll engine checks focus based on getBoundingClientRect() without any delay.
